## 4. PLAN：三张表列头与覆写纪律

`<交接区>\PLAN.md` 是**覆写式**文件（`<交接区>\PLAN.md:3`：「覆写式文件：**只改内容，保留结构**」）：每次编辑都是「读全文 → 改自己那几行 → 整篇写回」。

三张表的列头**原样**引用（`<交接区>\PLAN.md:21`、`:30`、`:43`）：

```text
| 会话 | 工作流 | 分支 | 当前顶端 | 状态 | 占用文件 |
| # | 从 → 到 | 内容 | 可执行 / 判据 | 状态 |
| # | 事项 | 负责人 | 为什么 | done 判据 |
```

三条写入纪律：

1. **各会话只改自己那一行**：「工作流」表里 A 只改 A 行、B 只改 B 行；要改对方的行或规则本身，先在 `<交接区>\LOG.md` 提出，**由用户裁决**（`<交接区>\README.md:23`）。
2. **覆写只改内容，保留结构**：`##` 标题数、表格列头、列数都不动（`<交接区>\PLAN.md:3`）。结构不变的判据：

   ```powershell
   (Select-String -LiteralPath '<交接区>\PLAN.md' -Pattern '^## ').Count   # 期望 5
   ```

   2026-10-15 实跑 = 5，即 `## 1. 工作流`（`<交接区>\PLAN.md:19`）、`## 2. 交接点`（`<交接区>\PLAN.md:28`）、`## 3. 待对方做的事`（`<交接区>\PLAN.md:41`）、`## 4. 已知红项与红线`（`<交接区>\PLAN.md:68`）、`## 5. 参考件（同目录，历史报告）`（`<交接区>\PLAN.md:78`）。`<交接区>\LOG.md:82` 记的正是这条口径：「结构保持：`PLAN.md` 仍是 5 个 `##` 标题」。

3. **「占用文件」列的写法**（实例 `<交接区>\PLAN.md:23-24`）：写「仓库文件：`<路径>`（在 `<分支>` 上，**不在** `<分支>` 上）」；已交回时写「**无（已交回）**」。不要写「我大概会用到的目录」这种范围句。

**跨占用（要动对方「占用文件」列里的文件）**：先在 `<交接区>\PLAN.md` 的「交接点」表**新增一行** + 在 `<交接区>\LOG.md` **追加声明**，等对方在 `<交接区>\LOG.md` 确认或撒手再动（规则行 `<交接区>\PLAN.md:34`，协议 `<交接区>\README.md:25`）。

**交接点只写事实与命令**（`<交接区>\README.md:26`）：写「我落了 `X`、顶端是 `Y`、你可以 `git cherry-pick Y`、期望看到 `Z`」；**不写意图、不写「稍后应该会」**。判据：「可执行 / 判据」列必须有一条能原样粘贴的命令或一个可观察结果（实例 `<交接区>\PLAN.md:36`、`<交接区>\PLAN.md:39`）。

## 6. 一卡一 worktree：写卡隔离命令

隔离是 §5 失败模式 1/2 的根因级处置：并行会话**开自己的 worktree + 自己的分支**，别在主检出里写；主检出留给正在跑门禁的一方收尾（`<交接区>\learn-model-work-split-2026-10-14.md:13`、`:18`）。

```powershell
# 并行会话：开 worktree + 自己的分支（各自独立索引与 HEAD）
git -C <业务仓库> worktree add `
  <业务仓库>-gpu -b feat/gpu-channel
# 之后所有改动、add、commit 都在那个目录里做
```

（命令原文 `<交接区>\learn-model-work-split-2026-10-14.md:53-58`。）做**摘要/字节敏感**验证（清单 sha256、bundle digest）时 worktree 必须建成 LF：

```powershell
git -C <业务仓库> -c core.autocrlf=false -c core.eol=lf `
  worktree add --detach <路径> <修订>
```

（命令原文 `<交接区>\learn-model-work-split-2026-10-14.md:82-84`。）

判据与配套纪律：

- `git -C <业务仓库> worktree list` 的每一项都能对上某张写卡的「分支 / 占用文件」字段。
- 同一个分支不能同时 checkout 到两个 worktree ⇒ 进 worktree 的一方**必须换自己的分支**（`<交接区>\learn-model-work-split-2026-10-14.md:51`）。
- 不要动别人的临时 worktree（`<交接区>\learn-model-work-split-2026-10-14.md:159`）；清理前先留底：取证无独有提交、无 stash，`git bundle create --all` 存底（实例 `<交接区>\LOG.md:34`：7 个 worktree 全部 `git worktree remove --force` exit 0、`git worktree prune` 无输出、`git worktree list` 只剩主树）。

## 7.5 回执与唤醒：outbox 约定（2026-10-15 实测补写）

排期与唤醒是两件事：**排期**是"到点起一个新会话"（见 `references/session-scheduling.md`），**唤醒**是"投给一个已存在的空闲会话，让它开新回合"。后者本机已可用，但投递是**单向**的——干完不会通知发起方，所以必须自己有回执落点。

| 动作 | 命令 / 位置 | 判据 |
| --- | --- | --- |
| 唤醒 | `pwsh -File <交接区>\knock.ps1 -SessionId <会话id> -Card <卡号>` | 该会话出现新回合；看不到新回合就是**未投递**，不许写成"已唤醒"。卡的负责人代号必须与目标会话在常驻 worker 表里的登记一致，否则拒投 |
| 信封 | `<交接区>\outbox\<knock_id>.history.json` | 发出时固化判据 `criteria_sha256`、`criteria_ids`、`target_session` 与 execution fact；**cron 任务保留到复核完成**（`knock.ps1 -Card <卡号> -DeleteTask -TaskId <knock_id>` 收口） |
| 回执 | `outbox\<卡号>-receipt.md`（人读）+ `outbox\<knock_id>.receipt.json`（机器） | `.md` 必须含 `KNOCK: <id>` 与 `STATUS: OK\|FAIL\|BLOCKED`，且与 JSON 的 `status` **逐字一致**；JSON 必须过 `references/receipt.schema.json` |
| 复核 | `python <技能目录>\scripts\verify_receipt.py --card <卡号> --knock <knock_id>` | 三态 `PASS(exit 0) / FAIL(1) / DEGRADED(2)`；**只报告不阻断**，判 FAIL 仍进 Done 必须在卡上写理由 |

三条硬约束（违反即静默失败）：①**归档会话投不进去**（宿主 `ArchivedSessionGate` 命中即拒，回合以 `blocked` 结束、零 token；投前查 `~\.dsh\storages\workspace.json` 的 `global.archivedSessionIds`）②**正在跑的会话不能 resume**（默认拒投，`-Force` 才硬试）③**回执要自己拉**（投递单向）。

两条新增（2026-10-15 契约 v1）：④**判据漂移**——发出后改过卡上判据，信封哈希对不上，复核器判 DEGRADED，本轮回执不能对账；⑤**同卡多轮**——`round` 递增，只有最后一轮能进 Done，历史轮次留在 `.md` 里不覆盖。

完整契约（物证类型与等级、T2/T3 档位、三段式升级、双看板权威、技能源同步）见 `references/receipt-contract.md`。

边界：唤醒通道依赖 `dsh-cron` 的 `targetSessionId` 与**本地补丁**（任务字段 `sessionId` → `resumeSessionId`），不是上游原生字段；换机器要重打补丁。

## 7.6 看板产物化、控制台与复核记账（2026-10-16 决策 R13/R14 补写）

到 2026-10-16，卡已经有九张、常驻会话三个，三处结构性问题必须收掉：**A/B 并发编辑同一份 75 KB 看板**（实测撞过 `FS_STALE_VERSION`）、**卡不可机器读**（W 每次要读整本看板才知道干什么）、**复核结论散在卡内证据段**（回答不了"谁在什么时候依据哪几个字节判过哪一敲"）。

| 对象 | 唯一可改处 | 产物（不许手改） | 判据 |
| --- | --- | --- | --- |
| 一张卡 | `_handoff\cards\<卡号>.yaml`（或 `board.py add/move/set`） | `_handoff\BOARD.md` | `board.py render` 后 `--check` 幂等通过；搬列时 `--note` 写证据 |
| 看板骨架 | `_handoff\board.skeleton.md` | 同上 | 常驻 worker 表、敲门硬约束、列标题、卡模板、顶部横幅都在骨架里 |
| 复核结论 | ——（由 `verify_receipt.py` 追加） | `_handoff\ledger\verdicts.jsonl` | 一敲一条：`at/card/knock_id/status/exit_code/criteria[]/receipt_sha256/board_sha256/operator`；`--no-ledger` 只报告不记账（巡检会话只许用这一档） |
| 审计历史 | —— | `_handoff\.git`（自有仓库） | `.gitignore` 排除 `*.bundle`/`wwtp-runs/`/`research\_backup-*`；`core.autocrlf=false` 保回执字节 |

派活的正常流程（`scripts/collab_console.py`，全部只走公开接口）：

1. `lease <卡> --by <代号>` —— 占住这张卡，A/B 不会同派一张（收口时自动释放）。
2. `budget` —— 看今日敲门累计 token 与上限（默认 12,000,000，`--daily-tokens` 可调）；**超限 exit 3 ⇒ 当天停派**（这是闸门，不是告警）。
3. `dispatch <卡>` —— 默认**异步**：建一次性任务（`schedule: in 1m`）+ 写 brief `outbox\<knock_id>.brief.md` + 落信封，**投递即返回**。三守卫与 `knock.ps1` v2 同源（负责人绑定 / 未归档 / 未在运行）。**不要**改用同步 `run`：客户端一断，宿主会把那一轮 dispose 掉（2026-10-15 探针 600 s 超时即被 `aborted/disposed`）。
4. `collect` —— 回填任务状态/耗时/token 到信封；`--verify` 顺手复核 + 记账。
5. `verify --card <卡> --knock <knock>` —— 三态结论 + 自动记账（薄封装 `verify_receipt.py`）。
6. `close --knock <knock> [--move-done]` —— 只在 `ledger` 里已有该敲的 **PASS** 时才删 cron 任务并释放租约；`--move-done` 顺便把卡搬进 Done（走 `board.py move` + `render`）。

代价与红线：多一层"yaml → render"的心智负担，**手改 `BOARD.md` 会在下一次渲染被静默覆盖**（顶部有横幅，`README.md` 第 10 条与巡检岗位规则都重复了这一点）；不引入数据库/服务化看板、不做实时双向同步——DSH 台账仍然是只读执行事实（ADR 0001）。

## 7.7 工人会话轮转（2026-10-16 决策 R9 补写）

一个常驻工人会话被反复敲门，上下文会一直涨（实测 W 跑到 ≈250 万 token 仍在工作）。轮转 = **换一个新的工人会话，把旧会话留在原地不再敲**——不是搬上下文。

```powershell
& $py "<技能目录>\scripts\collab_console.py" rotate W --dry-run --reason "<为什么换>"
& $py "<技能目录>\scripts\collab_console.py" rotate W --reason "<为什么换>"
```

它做的四件事（全部走公开接口）：①用 cron 起一个新会话（任务 `rotate_HHMMSS_NNN`、`schedule: in 1m`、同步 `run` 等它回一行 `READY`，约 10 s）；②从 `/history` 取新会话 id；③把 `board.skeleton.md` 里该代号的旧会话 id 换成新的并 `board.render`（看板是产物）；④把一条记录追加到 `ledger\rotations.jsonl`，随后删掉开机任务。

| 硬约束 | 说明 |
| --- | --- |
| 轮转前先 `collect` | 还有在途回执的旧敲门仍写在旧会话里，轮转后没人会去收 |
| 旧 id 必须在骨架里 | 找不到就报 `skeleton_stale`（说明有人手改过骨架或看板），不许猜 |
| 新会话没有旧上下文 | 卡必须自足：brief 里带整张卡原文，别让工人去"回忆上次" |
| 旧会话不删除 | 它的转写留在 `~/.dsh/sessions`，轮转只是不再投递 |

实测（2026-10-16 00:52 首次真轮转）：`cron-exec-worker_boot-0c68dadd…` → `cron-exec-rotate_005148_810-49df5611…`，`board.render` exit 0，记录进 `ledger\rotations.jsonl`。

## 7.8 一卡一工作树与工作集声明（2026-10-16 决策 R18 补写）

隔离命令（由 `dispatch --worktree <仓库>` 自动执行，也会写进 brief）：

```powershell
git -C <仓库> worktree add -b card/<卡号> %TEMP%\wt-<卡号>-<HHMMSS> <基点 HEAD>
```

派卡时任务 cwd 直接指向该工作树，信封记下基点 HEAD；工人只在这个工作树里改文件，主检出不动。

| 机制 | 判据 |
| --- | --- |
| 工作集声明 | 卡上 `workset`（`board.py set <卡号> workset=a/,b.md`，或派发时 `--workset`）写进信封与 brief；brief 明写"除这些路径外不许改" |
| 收口核对（机械） | `close` 用 `git diff --name-only <基点>` + `git diff --name-only` + `git ls-files --others --exclude-standard` 取改动集，再按工作集前缀判越界；越界清单与"工作树是否脏"写进信封 |
| 越界处置 | 默认只报告；`--strict` 越界即 exit 3（不改判定）；`--worktree-remove` 删工作树（脏或越界时自动 `--force`），**分支 `card/<卡号>` 保留**给人合并或丢弃 |

一句实话：工作树隔离的是**文件树**，不是 `.git`——对象与引用仍与主仓库共享，且工人 shell 在技术上仍能写工作树之外的路径（brief 禁止，`changed_files` 也只看工作树）。所以它是机械的可核对隔离，不是安全边界；真正的边界仍是权限与会话的作用域。

**落点必须在沙箱可写根之内**（2026-10-16 实测事故）：第一版把工作树放在 `%TEMP%\wt-<卡>-<时刻>`，工人第一次写就 `Access to the path … is denied`——DSH 文件沙箱只放行工作区根，`%TEMP%` 不在其中；工人于是申请提权（`danger-full-access`），而无人值守的敲门没有人批准 → 整轮挂在审批上直到超时。所以：**仓库与工作树都要落在可写根内**（默认 `<工作根>\_worktrees\`，可用 `COLLAB_WORKTREE_ROOT` / `COLLAB_SANDBOX_ROOTS` 覆盖），`dispatch` 会在派发前就拒掉根外的落点；brief 里也明写"被拒绝就停下报 BLOCKED，不要申请提权"。

实测（2026-10-16，一次性仓库）：`worktree add` → 改 3 个文件 → 工作集 `model_lab/` 下正确报出 2 处越界（`docs/a.md`、`extra.txt`）→ `worktree remove` 后目录消失、分支 `card/Z9` 保留。

## 7.9 落地：把卡分支并回主检出（2026-10-16 R18 第二阶段补写）

工作树隔离的代价是「成果停在一条分支上」。落地由 `land` 动词做完，**只做本机合并，绝不推送**：

```powershell
& $py "<技能目录>\scripts\collab_console.py" land --knock <knock_id> --into <主检出> --delete-branch
```

前置（缺一即拒，`--force` 才越权）：信封存在 → 该敲在 `ledger/verdicts.jsonl` 里有 PASS（FAIL 一律拒；DEGRADED 需卡上 `degraded_reason`，由 `close --accept-degraded "理由"` 写入）→ 主检出**没有已跟踪的未提交改动**（未跟踪文件不算；要带着脏树落地得显式 `--allow-dirty`）。

落地计划只有三种，其余一律停下问人：

| 计划 | 条件 | 动作 |
| --- | --- | --- |
| `ff` | 主检出 HEAD 就是信封记的基点 | `git merge --ff-only card/<卡号>` |
| `cherry-pick` | 主检出已前进，但基点仍是 HEAD 的祖先 | `git cherry-pick <基点>..card/<卡号>`（失败即 `--abort`，主检出回到动手前） |
| `noop` | 分支已经并进主检出（**先判这一条 ⇒ 重复落地幂等**），或分支相对基点没有新提交 | 什么都不做 |

拒绝条件：信封没记基点（`--base` 可补）、仓库里没有该分支、**基点不是主检出 HEAD 的祖先**（说明主检出动过、可能被回退或换分支——脚本不猜，交人处理）。

每次真落地都在 `ledger/landings.jsonl` 留一行（`mode`/`before_head`/`after_head`/`landed_commits`/`dirty_allowed`/`branch_deleted`），并写回信封的 `landed` 块；`--delete-branch` 先试安全的 `-d`，摘取落地时退化为 `-D`（原提交 sha 已在账里，删分支不丢证据）。**推送仍然只能由人逐次授权**——`land` 里没有任何远端写。

实测（2026-10-16，一次性仓库 + 卡 X3）：`land_plan` 判 `ff` → 主检出 `b10b820` 快进到 `6129269`、`note.md` 到位；再跑一次 = `noop`（幂等）；`--delete-branch` 在分支仍被工作树占着时报 `cannot delete branch … used by worktree` 并**拒绝假装成功**，`git worktree remove` 之后同一条命令 `-d` 删成功。自测 10 项（ff / noop / 四条拒绝线 / 摘取 / 幂等 / 删除被拒 / 删除成功）随 `collab_console.py selftest` 跑，25/25 通过。

## 7.10 排队、通道健康、换绑与一键停机（2026-10-16 R52 补写）

**排队＝信封已写、任务未投**（不新增存储、不建队列服务）。`dispatch --when-idle` 在目标会话正在跑时不报错，把信封标成 `delivery: pending` 并写 `queued_at`/`queue_deadline`；`collect`（以及任何动词开头）会先尝试投递：目标空闲 ⇒ 建任务并写 `delivered_at`；目标被归档或超过 `queue_deadline`（默认 4 小时）⇒ 改成 `abandoned` 并在信封写明原因，`status` 与巡检报红。老信封没有 `delivery` 字段＝当时是同步投的，视为已投。

**任务体止损**：任务体带 `timeoutSeconds`（`dispatch --timeout`，默认 900）与 `maxRetries`（默认 0）。宿主语义是到点中止这一轮并释放会话——**这是本体系唯一的「停止」手段**（看板的卡没有停止按钮，已经投出去的活停不下来）。

**通道健康三判据**（`status` 的「通道健康（R52-4）」节，逐条 `[OK]`/`[注意]`/`[未知]`）：

1. `patch`：`dsh-cron` 的 `lib/runner.js` 里唤醒用的键名仍是宿主契约要求的 `resumeSessionId`。插件升级会覆盖这个补丁；重打办法见 `_handoff/README.md`，巡检只报不打。
2. `bindings`：worker 表里每个非 A 代号都在会话名册里且未被归档。**名册＝工作区注册表 ∪ `~/.dsh/sessions/<编码后的 cwd>/<会话 id>`**——调度器铸出来的会话不一定写进注册表，只认注册表会把健康登记误报成「不在会话名册里」（2026-10-16 实测踩到并修）。
3. `board`：`board.py render --check` 通过（有人手改 `BOARD.md` 就报红）。

读不到就报「未知」——**未知不是正常**。

**换绑（`bind`）**：只接受「名册里存在 + 未归档」的会话；写 `board.skeleton.md` → 重渲染 → 记一条 `ledger/rotations.jsonl`；重渲染失败即回滚骨架。`workers` 列出候选（名册 ∩ 未归档）与当前登记。日常换人也可以用 `rotate <代号>`（§7.7）。

**一键停机（`stop-all`）**：只删控制台铸的任务（id 前缀 `knock_`/`rotate_`/`probe_`/`worker_boot`/`palimpsest_probe`），保留巡检等常设排期（`--keep` 可加前缀）；输出在跑会话与剩余排期，并明说**不会中断已经启动的那一轮**。

## 8. 敏感内容禁写清单

交接区**不在 Git 里**，但会被双方读进上下文（`<交接区>\README.md:28`）——清单的作用是「别把它读进模型上下文、别在发布物里复现」，不是行政密级。

一律不写进交接区（`<交接区>\README.md:28`）：

| 类别 | 判据（出现即违规） | 替代写法 |
| --- | --- | --- |
| 真实点位码 / 测点编号 | 与真实工程绑定的编号 | 写 `<点位码>` 或只写「点位码」 |
| 平台 run id | 上传/训练/推理的运行标识（长十六进制串） | 写 `<run id>`；确需留痕时只写前缀片段 |
| 凭据 | 任何 access key / secret / token / 口令 / 私钥块，含混淆载荷 | 只记机制与核验结果：不抄、不落任何凭据载荷；测试里的密钥字面量改成运行期拼接（`<交接区>\PLAN.md:45`），`LOG.md` 里只登记「敏感词表 + 命中 0」这一事实（`<交接区>\LOG.md:90`） |

### 8.1 扫描闸门自己也会假绿（2026-10-16 实测，代价 = 一次已推送）

生成公开副本（`<技能源>\tools\export-public.ps1`，白名单 + 占位化 + 导出自检）时，我在推送前又加了一道「遍历**已跟踪文件**重扫」的闸门，它打印 `0 命中 ✓` —— **但四个中文文件名的 ADR 一个都没被读到**：`git ls-files` 默认 `core.quotepath=true`，把非 ASCII 路径输出成 `"docs/adr/0001-\344\270\244..."`（引号 + 八进制转义），`Join-Path` 拼出的路径无效、`ReadAllText` 抛异常，而我的判断**没把异常算作失败**。当时仓库已经推上去了（随后用 `git grep` 复扫才确认内容其实干净）。

两条正确写法，任一即可：

```powershell
# ①扫【已提交内容】：直接搜 blob，不经过工作区路径，中文路径也不受影响
git -C '<仓库>' grep -n -I -E '<模式>' HEAD --     # 退出码 1 = 无匹配，不是错误

# ②扫【工作区】：遍历文件系统，而不是 git ls-files
Get-ChildItem -Recurse -File '<目录>' | Where-Object { $_.FullName -notmatch '\\\.git\\' } |
  ForEach-Object { Select-String -LiteralPath $_.FullName -Pattern '<模式>' }
# 非要用 git ls-files 时：git -c core.quotepath=false ls-files（或 -z 后按 \0 切分）
```

纪律两条：**扫描器的异常必须算失败**（`$ErrorActionPreference='Stop'`，或逐文件 `try/catch` 把异常计入命中数），因为「没报错 = 没命中」正是这类闸门最容易骗人的地方；**闸门只在被绕过时才知道自己漏了**，所以「0 命中」这句话必须能追到具体命令与退出码，否则只能报「未核验」。

另一条同源经验：脱敏替换要覆盖 **JSON/源码里的双反斜杠写法**（`<交接区>`）——`export-public.ps1` 第一次跑就是被自己这条自检拦下的，只替换单反斜杠形式会在 `.py` 的默认值与 `.md` 的示例里漏网。
