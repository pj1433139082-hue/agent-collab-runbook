# ADR 0002 · 看板产物化与复核记账

- 状态：已接受（2026-10-16）
- 决策者：业主 + 会话 A
- 相关：`CONTEXT.md`（卡数据源 / 渲染 / 复核记账 / 租约 / 预算闸 / 敲门简报 / 异步派活），`skill/agent-collab-runbook/references/receipt-contract.md`，`scripts/board.py`、`scripts/verify_receipt.py`、`scripts/collab_console.py`

## 背景

到 2026-10-16 凌晨，交接区已经是**实体系统**而不是笔记：9 张卡（A1–A5 / B1–B4 / W1–W6 / X1）、一个常驻 worker（W）、一个巡检会话（P）、一条已验证的唤醒通道（`dsh-cron` + 本地补丁）、一个回执契约与复核器。三处结构性问题随之暴露：

1. **并发编辑撞在同一个文件上**：A 与 B 同时改 75 KB 的 `BOARD.md`，实测触发过 `FS_STALE_VERSION`；卡的增减、搬列全是自由文本编辑，没有幂等性。
2. **卡不可机器读**：判据以散文写在卡里，只有 `knock.ps1` 借 `verify_receipt.py --print-card-facts` 临时抽一次；W 每次被唤醒要读整本看板（约 75 KB）才知道自己该干什么。
3. **复核不可审计**：复核发生在会话上下文里，结论写进卡内证据段。没有任何地方能回答"谁在什么时候、依据哪几个字节的哈希、把哪一敲判成了 PASS"。

## 决策

1. **卡数据进 `cards/<卡号>.yaml`**（JSON 兼容），字段 `id/column/owner/depends_on/scope/updated/body`；`body` 保留卡原文（含判据）。`BOARD.md` 由 `scripts/board.py render` 从「卡数据 + `board.skeleton.md`」渲染，**不再手改**。
2. **骨架独立**：固定段落（常驻 worker 表、敲门硬约束、五列标题、卡模板、横幅）放 `board.skeleton.md`；`render` 把卡插进 `<<<CARD 卡号>>>` 占位处。
3. **产物横幅**：`BOARD.md` 顶部显式写明"本文件是产物，请勿手改（R13）"，并给出改卡的两种正确路径（`board.py add/move/set`，或改 yaml 后 `render`）。
4. **迁移以"往返一致"验收**：一次性 `board.py migrate` 从旧 `BOARD.md` 切出卡与骨架；验收标准是 `render` 出的正文与原文一致、且 `render --check` 幂等通过。
5. **复核结论追加进 `ledger/verdicts.jsonl`**（决策 R14）：一敲一条，含 `at/card/knock_id/status/exit_code/criteria[]/receipt_sha256/board_sha256/operator`。`verify_receipt.py` 默认写账，`--no-ledger` 只报告；巡检会话只允许以 `--no-ledger` 跑。
6. **`_handoff` 有自己的 Git 仓库**：`git init`（2026-10-16）、`.gitignore` 排除 `*.bundle`/`wwtp-runs/`/`research\_backup-*` 等大件、`core.autocrlf=false`（保住回执字节），使"看板变更"与"复核账目"都可 diff、可回滚、可审计。
7. **派活的两道前置闸门写进工具**（不靠自觉）：`collab_console.py lease <卡> --by <代号>` 占住卡；`budget` 比对今日累计 token 与上限（默认 12,000,000），超限 exit 3。

## 后果

- 好处：并发编辑的冲突面从「整本看板」缩到「单卡文件」；卡状态可由脚本搬列并附证据行；复核可审计、可统计；W 只需读随敲门下发的 brief（约 2–3 KB）而不是整本看板。
- 代价：多一层心智负担（yaml → render），手改 `BOARD.md` 会在下一次渲染被静默覆盖——因此横幅、`README.md` 第 10 条与巡检岗位规则都必须重复这一点。
- 迁移期容忍历史卡的散文体：`body` 原样保留，结构化程度由新卡逐步提高。
- **不引入**：数据库/服务化的看板、实时双向同步、把任务语义迁进 DSH 台账（ADR 0001 仍然有效：台账是只读执行事实）。

## 被否决的替代方案

- **继续手写 `BOARD.md`，只加一致性校验**：解决不了并发编辑与机器统计，校验只能事后发现冲突。
- **以 DSH 任务看板为唯一来源**：卡 `prompt` 开始执行后冻结、无判据字段、只能被工具读不能被 diff（ADR 0001 已否决）。
- **复核结论只写卡内证据段**：不可统计，也无法回答"哪一版回执字节被判过"。
- **每次复核后手工记一行到 `LOG.md`**：`LOG.md` 是叙事时间线，做审计账目会污染它，且无法机器比对。
