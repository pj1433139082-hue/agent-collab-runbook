# 0004 落地只经 `land`，且绝不推送

- 状态：已接受
- 日期：2026-10-16
- 相关：`references/handoff-protocol.md` §7.9、ADR 0003（会话轮转与一卡一工作树）、`scripts/collab_console.py`

## 背景

一卡一工作树（ADR 0003）让每张写卡在自己的检出里干活，代价是成果停在一条 `card/<卡号>` 分支上——总得有人把它并回主检出。

人工合并正好落在 2026-10-14 那次事故的同一类风险里：主检出是共享的，`git add`/`merge` 在共享索引上留下的中间态会让别人的在途改动凭空消失。而"自动化顺手帮我并一下"又直接通向另一个诱惑：既然都并了，何不顺手推上去。

## 决定

1. **落地是控制台的一个动词**（`land`），不是人工 `git merge`。卡片分支不允许手并；要落地就走 `land`，让计划、拒绝条件与记账都在同一条路径上。
2. **只有三种计划**：`ff`（主检出 HEAD 就是信封记的基点）、`cherry-pick`（主检出已前进但基点仍是 HEAD 祖先）、`noop`（分支已并入或没有新提交）。**其余一律拒绝**。
3. **幂等先判**：「分支已经并进主检出」这条在需要基点之前判——重复落地必须无副作用；信封丢了基点不该让一张已经落过的卡变成报错。
4. **四条拒绝线**：该敲没有 PASS 复核结论（FAIL 一律拒；DEGRADED 需卡上 `degraded_reason`）；主检出有**已跟踪**的未提交改动（未跟踪文件不算；确要带着脏树落地得显式 `--allow-dirty`）；信封没记基点（可用 `--base` 补）；**基点不是主检出 HEAD 的祖先**（说明主检出动过、可能被回退或换分支——脚本不猜，交人处理）。
5. **只做本机合并，绝不推送**。`land` 里没有任何远端写；推送仍然只能由人逐次授权。这条是硬边界，不是默认值。
6. **每次落地都记账**：`ledger/landings.jsonl` 一行含 `mode`/`before_head`/`after_head`/`landed_commits`/`dirty_allowed`/`branch_deleted`，并写回信封的 `landed` 块。`--delete-branch` 先试安全的 `-d`，摘取落地退化为 `-D`——原提交 sha 已进账，删分支不丢证据。
7. **失败即回退**：`cherry-pick` 冲突立刻 `--abort`，主检出回到动手前的状态，绝不留下半成品或冲突标记。

## 被否决的方案

- **在 `close` 里顺手落地**：收口与落地是两种风险。收口删任务、放租约，都在交接区；落地会改主检出。混在一起就没有"复核过但还不落地"这个状态，而那个状态正是人做最后判断的地方。
- **自动 rebase 分支到最新再 ff**：冲突会在没人看的时刻被解决（或解错），而且 rebase 改写了卡分支的 sha，回执里引用的 commit id 会对不上。
- **自动推送**：越权。远端写必须逐次授权，这一点不因为"已经复核过"而改变。
- **只支持 ff**：真实主检出一动，ff 就废；那样等于逼人手工 merge——正是本 ADR 要消除的东西。

## 后果

- 主检出里的每一次变更，都能追到一张复核过、记过账的卡。
- 代价：主检出必须先干净（这是保护，不是限制）；`cherry-pick` 落地会生成新的 commit sha，原 sha 只存在于 `landings.jsonl` 里，所以**落地后不要删账本**。
- 自测（`collab_console.py selftest`）用真 git 仓库覆盖 ff / cherry-pick / noop / 四条拒绝线 / 幂等 / 删除分支被拒与成功共 10 项，25/25 通过——落地逻辑不允许只有"跑过一次"这一种证据。
- 实测（2026-10-16，卡 X3 + 一次性仓库）：`ff` 落地、重复 `land` 幂等、`--delete-branch` 在分支被工作树占着时**带 git 原因拒绝**（不假装成功），移走工作树后删除成功；两条记录都在 `ledger/landings.jsonl`。
