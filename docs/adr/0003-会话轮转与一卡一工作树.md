# ADR 0003 · 会话轮转、一卡一工作树与降级放行

- 状态：已接受（2026-10-16）
- 决策者：业主 + 会话 A
- 相关：`CONTEXT.md`（会话轮转 / 工作集 / 工作树 / 降级放行），`docs/adr/0002-看板产物化与复核记账.md`，`skill/agent-collab-runbook/references/handoff-protocol.md` §7.7–§7.8，`scripts/collab_console.py`

## 背景

控制台上线（ADR 0002）后，三处缺口立刻变成可测量的：

1. **工人上下文无限增长**：常驻 W 走的是 `reuseSession`，每敲一次都在同一个会话里续。实测单次派遣 131,904–353,121 ms、1,173,792–2,519,334 tokens；到 2026-10-16 凌晨，W 的会话已经积累到约 250 万 token 仍在工作。宿主没有任何"换掉这个常驻会话"的官方动作。
2. **一卡一工作树只是纸面纪律**：`handoff-protocol.md` 早就写了隔离命令，但没有任何机械核对——谁改了"占用文件"之外的路径，只能靠人读 diff。
3. **DEGRADED 是常态却没有处置规则**：W1–W6 六次复核的实测结论是 PASS / PASS / FAIL / DEGRADED / DEGRADED / PASS。旧回执（W1–W5）本就不可复算，所以 DEGRADED 会一直出现；但"能不能进 Done"没有规则，容易退化成"反正报告里写了"。

## 决策

1. **会话轮转**＝起一个新会话 + 改骨架里的会话 id + 重渲染 + 记 `ledger/rotations.jsonl`（`collab_console.py rotate <代号>`）。旧会话**不删除、不再投递**。
2. **轮转不做上下文迁移**：新会话什么都不知道，所以卡必须自足（brief 带整张卡原文）。这与 ADR 0002「卡可机器读」同向。
3. **轮转前必须 `collect`**：还在等回执的敲门仍写在旧会话里，轮转后没有发起方会去收它。
4. **一卡一工作树**：`dispatch --worktree <仓库>` 执行 `git worktree add -b card/<卡号> %TEMP%\wt-<卡号>-<HHMMSS>`，任务 cwd 指向该工作树，信封记下基点 HEAD；主检出不动。
5. **工作集声明进卡与信封**：卡的 `workset` 列（或派发时 `--workset`）写进信封与 brief；收口时用 `git diff --name-only <基点>` + `git diff --name-only` + `git ls-files --others --exclude-standard` 取改动集，按前缀机械核对越界。
6. **越界只报告、不改判定**：`close --strict` 是"越界即 exit 3"的报告档，不是门禁；删工作树时若脏或越界自动 `--force`，**分支 `card/<卡号>` 保留**给人合并或丢弃。
7. **降级放行**：`DEGRADED` 可以进 Done，但必须写下理由（`close --accept-degraded "<理由>"` 或卡上 `degraded_reason`），理由进卡与账目；`FAIL` 一律不许放行（`close` 直接拒）。
8. **三样都不新增常驻服务**：全部落在控制台、看板产物与 git 原语里，不引入容器、克隆池或调度器。

## 后果

- 好处：工人上下文有上界（换会话即可）；卡的作用域从"口头声明"变成"可机械核对的差分"；"Done"的含义与复核三态绑定，放行理由留痕可查。
- **诚实限制一**：工作树隔离的是**文件树**，不是 `.git`——对象与引用仍与主仓库共享，且工人 shell 在技术上仍能写工作树之外的路径。它是可核对的隔离，不是安全边界；真正的边界仍是宿主权限与会话作用域。
- **诚实限制一之补充（实测事故）**：工作树落点**必须在沙箱可写根之内**。第一版落在 `%TEMP%\wt-<卡>-<时刻>`，工人第一次写入即 `Access to the path … is denied`（文件沙箱只放行工作区根），随后它申请 `danger-full-access` 提权——无人值守的敲门没有人会批准，整轮挂在审批上直到 30 分钟超时。因此：仓库与工作树都落在可写根内（默认 `<工作根>\_worktrees\`），`dispatch` 派发前拒掉根外落点，brief 明写"被拒绝就停下报 `BLOCKED`，不要申请提权"。这条约束比"隔离"本身更容易被忽略，所以写进 ADR 而不是只写进代码注释。
- **诚实限制二**：轮转丢上下文。卡写得不清，新工人就会重问一遍；这是用"卡自足"换"上下文有界"。
- **诚实限制三**：降级放行是人的判断，账目只保证"有人为这一次签了字"，不保证判断正确。
- 代价：控制台多两个动词（`rotate`、`close --worktree-*`）与两条可测不变量；`_handoff` 多一个账目文件。

## 被否决的替代方案

- **每次派遣都新建会话（不复用）**：省掉轮转，但每张卡都要从零重建上下文，且失去"同一个工人"的连续记录。我们保留常驻工人，只在上下文涨到不该涨时换。
- **轮转时删除旧会话**：会丢掉 `~/.dsh/sessions` 里的转写，而转写是回执与账目之外的唯一调查线索。
- **用分支切换 / `git stash` 代替工作树**：切换分支会串改主检出——正是 2026-10-14「共享工作树导致 git add 被清空」的事故形态。
- **越界即阻断收口（`--strict` 设为默认）**：把报告变成门禁，反而会鼓励把越界路径提前塞进工作集清单里，越界就更看不见了。
- **给 DEGRADED 打"免责"标记直接跳过**：那就没有"谁签的字"，等于把常态降级变成默认放行。
